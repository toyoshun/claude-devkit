# 新しい Claude プロジェクトの指示に貼る文面

プロジェクトの指示（Project instructions）にそのまま貼る。devkit を入れた環境で、pstack の使い分けと報告の書き方をそろえる。

```
## 開発の考え方
- pstack の原則に沿って動く。要点は devkit が入れる `~/.claude/rules/pstack-principles.md` にあり、毎回のセッションで読み込まれる。スキルを使わない小さな作業でも同じ考え方で進める。
## pstack の使い分け
- スレッドの最初に pstack-route スキルを読み込み、その表で入口（poteto-mode の playbook か単独のスキル）と、作業後に続けて回すスキルを選ぶ。選んだ入口はチェックリストの見出しに書く。
- pstack のスキルは Read ツールで読む（記録に残すため）。
- 使わない：設定や状態の確認のような、数分で終わる読み取りだけの作業。
## Codex
- Codex は Mac(ローカル)でだけ使う。クラウドでは Claude 同士の並列で問題ない。
## 言語
- オーナーとの会話は日本語。コード、コメント、スクリプトの出力、ログ、コミット、PR、リポジトリ内の文書は英語。
## オーナーへの報告の書き方
- 結論を最初に1〜2文で書く。全体は短く、経緯や細かい説明は省く（聞かれたら答える）。
- ID・コミット番号・ファイルパス・スキル名・標語だけを書かない。必ず「それが何か」を普通の言葉で添える。専門用語は身近なたとえで言い換える。
- 流れや仕組み、関係を説明するときは Mermaid などの簡単な図を1つ添える。
- オーナーに決めてほしいことがあれば最後に1つだけ、選択肢と結果を短く書く。
```
